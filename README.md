# סליחות עדות המזרח

אתר סטטי־דינמי לסדר **סליחות נוסח עדות המזרח** — מנוקד ניקוד מלא, מעומד כסידור,
עם **מעקב חי אחרי הסליחות בכותל המערבי** שגולל ומדגיש את המילה שנאמרת ברגע זה.

## מה יש כאן

| רכיב | תיאור |
|---|---|
| `data/slichot.json` | סדר הסליחות המלא — 57 פרקים, 229 פסקאות, 5,391 מילים מנוקדות |
| `scripts/build_text.py` | בונה את מאגר הטקסט ממקור [ספריא](https://www.sefaria.org.il/Selichot_Edot_HaMizrach) (תורת אמת, נחלת הכלל), מתקנן את שם ה׳ ומפריד הוראות מהטקסט |
| `scripts/build_site.mjs` | מייצר `public/index.html` עם **כל** הטקסט מוטמע ב-HTML (SEO ללא תלות ב-JS), וכן `sitemap.xml` ו-`robots.txt` |
| `server/matcher.js` | מנוע ההתאמה: מוצא היכן אוחז החזן לפי תמלול משובש, בעזרת אינדקס תלת־גרמים + השוואת שלד עיצורי |
| `server/kotel.js` | צינור המעקב החי: שידור → `yt-dlp` → `ffmpeg` (קטעי WAV) → תמלול → התאמה → שידור מיקום ב-SSE |
| `server/analytics.js` | מדידת כניסות first-party ב-SQLite, ללא עוגיות צד שלישי, עם גיבוב IP |
| `public/admin.html` | לוח בקרה: מבקרים בזמן אמת, זמן קריאה, עומק גלילה, מקורות תנועה |
| `public/sync.html` | מסך סנכרון ידני לגבאי — לחיצה על מילה משדרת את המיקום לכל הקוראים |

## הרצה מקומית

```bash
npm install
cp .env.example .env     # ולמלא ADMIN_TOKEN לכל הפחות
npm start                # http://localhost:3000
```

## מעקב אחרי הכותל — איך זה עובד

1. השרת קולט את האודיו של השידור החי וחותך אותו לקטעי WAV של 8 שניות:
   - `KOTEL_STREAM_URL` שהוא **כתובת HLS ישירה** (`.m3u8`) נקלט ב-`ffmpeg` כמו שהוא.
   - כתובת יוטיוב עוברת דרך `yt-dlp -g` שמחלץ את ה-HLS בפורמט הזול ביותר (144p, ~290kbps).
     כשהכתובת פגה, המנוע מרענן אותה ומתחבר מחדש.

   > **יוטיוב חוסמת שרתי ענן.** מ-Render מתקבל
   > `Sign in to confirm you're not a bot`. המנוע מנסה חמישה לקוחות נגן שונים לפני
   > שהוא מוותר, ותומך בקובץ עוגיות דרך `YTDLP_COOKIES` — אבל הפתרון הנקי הוא
   > להצביע על כתובת HLS ישירה, שאינה עוברת דרך yt-dlp כלל.
2. כל קטע נשלח לתמלול בעברית (OpenAI או ElevenLabs Scribe).
3. `Aligner` מצליב את המילים המתומללות מול 5,357 מילות הסדר ומחזיר אינדקס מילה + רמת ודאות:
   - **איחוד שם ה׳** — הטקסט כותב `יְהֹוָה` והתמלול שומע `אֲדֹנָי`. שתי הצורות (וגם `ה׳`)
     מאוחדות לצורה קנונית אחת. שם ה׳ הוא 2.5% ממילות הסדר ומרוכז בנוסחאות החוזרות.
   - **שלד עיצורי** — הסרת אהו״י, כדי לספוג שגיאות כתיב מלא/חסר בתמלול.
   - **סריקה מקומית** — כשאין שלוש מילים רצופות תקינות (קורה בקטעי הארמית של "רחמנא",
     שהתמלול מרסק), ויש כבר מיקום ידוע, מדרגים חלונות סביבו לפי חפיפת מילים בודדות.
   - קפיצה רחוקה מתקבלת רק בוודאות גבוהה.
4. המיקום משודר ללקוחות ב-Server-Sent Events; הדפדפן מדגיש את המילה וגולל אליה.
5. בין תמלולים המערכת מקדמת את המיקום לפי קצב אמירה משוער (`KOTEL_WPM`).
6. הקליטה פועלת **רק כשיש מאזינים** ונעצרת אחרי שתי דקות בלי אף אחד.

ללא מפתח תמלול, `/sync` מאפשר לגבאי לסמן את המקום ידנית — והמעקב עובד בדיוק אותו דבר.

### תוצאות הניסוי

`npm run test:kotel -- <קובץ> --seconds 420` מריץ הקלטה דרך אותו צינור בדיוק ומדפיס
את מסלול הזיהוי. על 7 דקות הקלטה אמיתית של סליחות בנוסח ספרדי (ElevenLabs Scribe, קטעי 8 שניות):

| מדד | תוצאה |
|---|---|
| קטעים שזוהה בהם מיקום | 45 מתוך 53 (85%) |
| התקדמות סבירה לפי הזמן שחלף | 43 מתוך 44 המעברים |
| ודאות ממוצעת | 0.71 |
| רצף הפרקים שזוהה | לך ה׳ הצדקה → למענך אלהי → אדני שמעה → שבט יהודה → אל מלך יושב → ויעבור → רחמנא → ויעבור → אנשי אמונה אבדו |

רצף הפרקים תואם את סדר הסליחות בפועל. הקטעים שלא זוהו הם בעיקר שורות ארמית מושרות
שהתמלול מרסק — ושם נכנס הקידום המשוער לפי קצב האמירה. תמלולים נשמרים במטמון,
כך שכיול מנוע ההתאמה אינו עולה כסף על כל ריצה.

## משתני סביבה

ראו `.env.example`. החשובים: `ADMIN_TOKEN`, `SITE_URL`, `OPENAI_API_KEY` (או `ELEVENLABS_API_KEY`),
`ADSENSE_CLIENT` + `ADSENSE_SLOT_TOP/BOTTOM`, `GA_MEASUREMENT_ID`.

## פריסה ל-Render

הריפו כולל `render.yaml` ו-`Dockerfile` (עם `ffmpeg` ו-`yt-dlp`). ב-Render:
New → Blueprint → בחירת הריפו. השירות עולה בתוכנית החינמית.

> שימו לב: בתוכנית החינמית אין דיסק קבוע — נתוני האנליטיקס נמחקים בכל פריסה מחדש.
> לשמירה לאורך זמן יש לחבר Disk בתשלום ל-`DATA_DIR`, או להגדיר `GA_MEASUREMENT_ID`.
